# AMBRE 0.1 — Fondation fonctionnelle : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Livrer AMBRE 0.1. Le système synchronise en lecture les marchés binaires Manifold, les stocke avec leur horodatage, calcule une probabilité de référence, détecte des opportunités théoriques après impact CPMM, et passe chaque proposition par un moteur de risque et de survie. Il simule les décisions sur un portefeuille virtuel de 1 000 Mana, les journalise, et affiche marchés, capital et historique dans un dashboard.

**Architecture :** Monolithe modulaire Python (`src/ambre/`) avec des frontières strictes. Les appels réseau sont confinés à `integrations/manifold`, la persistance à `infrastructure`. Les calculs (valeur, risque, survie, prédiction) sont des fonctions pures sans E/S. Deux points d'entrée partagent ce paquet : un worker CLI (`ambre`) qui enchaîne sync → cycle de décision, et une API FastAPI en lecture, avec un seul endpoint d'écriture, l'arrêt d'urgence. Le dashboard Next.js (`apps/dashboard`) ne consomme que l'API.

**Tech Stack :** Python 3.12 (installé via `uv python install 3.12`), uv, FastAPI, Pydantic v2, pydantic-settings, HTTPX, SQLAlchemy 2, Alembic, SQLite par défaut et PostgreSQL via Docker Compose, pytest, pytest-asyncio, Hypothesis, Ruff, mypy. Côté front : Next.js (dernière version stable au moment de l'exécution, épinglée), TypeScript strict, Tailwind, shadcn/ui, TanStack Query, Recharts, Vitest.

**Spec :** `docs/superpowers/specs/2026-10-31-ambre-master-spec.md` (Partie XXIV = périmètre de ce plan ; le reste borne ce qu'on ne doit pas faire et prépare les interfaces).

## Global Constraints

- `EXECUTION_MODE=PAPER` et `ENABLE_MANIFOLD_ORDERS=false` par défaut. Aucun code de la v0.1 n'appelle `POST /v0/bet` ni aucun autre endpoint d'écriture Manifold. `MANIFOLD_MANA` lève `ExecutionModeNotAvailable`. La présence d'une clé API n'autorise rien.
- Capital virtuel initial : **1 000 Mana**.
- Paramètres de risque initiaux (expérimentaux, non optimisés) : `max_position_fraction: 0.02`, `max_total_exposure_fraction: 0.20`, `kelly_fraction: 0.25`, `minimum_edge: 0.03`, `critical_drawdown: 0.30`.
- Marchés traités : `outcomeType == "BINARY"` et `mechanism == "cpmm-1"` uniquement. Tout le reste (MULTIPLE_CHOICE, PSEUDO_NUMERIC, PERP, etc.) est stocké comme ignoré avec sa raison, et n'est jamais évalué. `token == "CASH"` est exclu.
- Endpoints Manifold autorisés (vérifiés le 2026-10-31 sur l'API réelle) : `GET https://api.manifold.markets/v0/markets` (`limit` ≤ 1000, `sort=updated-time`, `order=desc`, `before=<marketId>`, curseur confirmé fonctionnel avec `sort=updated-time`) et `GET /v0/market/{id}`. Limite : 500 req/min/IP. Aucun contournement, aucun scraping.
- Chaque snapshot de marché porte `observed_at`, `event_at` (= `lastUpdatedTime` Manifold, `None` si absent), `ingested_at` et `source_id`. Aucun prix n'est inséré avec une date inventée.
- Une donnée absente reste `None`. Elle n'est jamais remplacée par 0.
- Le kelly intégral n'est jamais utilisé. Kelly est toujours calculé sur une probabilité pénalisée par l'incertitude, puis plafonné par le moteur de risque.
- Les tests n'utilisent jamais Internet ni de vraie mise. Les fixtures Manifold sont enregistrées une fois via un script, et les fixtures construites à la main sont préfixées `synthetic_`.
- Aucun secret dans Git : `.env` est ignoré et `.env.example` est fourni.
- Docker n'est pas requis pour les tests (SQLite).
- Ne pas créer de fichiers ou modules vides pour les moteurs futurs (imitation, contexte, apprentissage, backtesting). Ils figurent dans `docs/ROADMAP.md`.
- Code et identifiants en anglais. Docs utilisateur en français.

## Review Focus

1. **Résolutions atypiques :** marché résolu `CANCEL` (remboursement de la mise), `MKT` (paiement à `resolutionProbability`), chaîne de résolution inconnue (position laissée ouverte et signalée dans le rapport de cycle, jamais réglée en silence), marché fermé mais non résolu (non éligible, position conservée). → tests dans la Tâche 8.
2. **Erreurs API en pleine pagination :** 429/5xx, puis abandon après les retries sur la page 3. Les pages déjà validées sont commitées, le watermark n'avance pas au-delà de la dernière page complète, et la synchro suivante reprend. Un JSON invalide ou un champ requis manquant sur un marché isolé le rejette avec une raison sans faire échouer la page. → tests dans les Tâches 4 et 6.
3. **Relance d'un cycle sur les mêmes données :** relancer `ambre cycle` deux fois sans nouveau snapshot ne crée aucune décision, aucune position ni écriture de ledger supplémentaire (clé d'idempotence). Un marché avec une position ouverte n'est jamais remisé. → tests dans les Tâches 8 et 9.
4. **Prix extrêmes et faible liquidité :** `q` = 0.01 ou 0.99, pool de 100 Mana. Les parts CPMM restent finies et positives, la mise reste ≤ 2 % de la valeur, ≥ 1 Mana sinon NO_TRADE, et l'impact peut faire passer l'edge sous 0.03, ce qui entraîne un refus. → tests dans les Tâches 3 et 7.
5. **Données périmées ou exposition indéterminable :** dernière synchro réussie il y a plus de `max_data_age_seconds` (900 s), ou jamais faite, ou base injoignable pendant le calcul d'exposition. L'état passe à `OBSERVING` et aucune nouvelle position n'est ouverte. → tests dans les Tâches 7 et 9.

### Tâche 3 : Mathématiques de valeur (CPMM, EV, Kelly)

**Files :**
- Create : `src/ambre/value_engine/cpmm.py`, `src/ambre/value_engine/value.py`
- Test : `tests/unit/test_cpmm.py`, `tests/unit/test_value.py`, `tests/property/test_value_properties.py`

**Interfaces :**
- Produces :
  - `cpmm_probability(pool_yes: float, pool_no: float, p: float) -> float` = `p*n / ((1-p)*y + p*n)`
  - `cpmm_shares(pool_yes: float, pool_no: float, p: float, amount: float, side: Side) -> float`
  - `@dataclass(frozen=True) class Fill: side, amount, shares, avg_price, prob_before, prob_after`
  - `cpmm_fill(pool_yes, pool_no, p, amount, side) -> Fill`
  - `ev_ideal(p: float, q: float, side: Side) -> float` (`p-q` ou `q-p`)
  - `kelly_yes(p, q) -> float`, `kelly_no(p, q) -> float` (formules de la spec, ≥ 0)
  - `@dataclass(frozen=True) class FillValue: fill: Fill, cost: float, expected_payout: float, expected_value: float, ev_per_mana: float`
  - `assess_fill(p_side: float, fill: Fill, fee_rate: float) -> FillValue`, avec `cost = amount*(1+fee_rate)`, `expected_payout = p_side*shares` et `ev_per_mana = expected_value/cost`. `p_side` est la probabilité de l'issue achetée.

Algorithme `cpmm_shares` (formule `calculateCpmmShares` de Manifold, invariant `k = y^p · n^(1-p)`) :
```python
k = y**p * n**(1 - p)
if side is Side.YES:
    return y + amount - (k * (amount + n) ** (p - 1)) ** (1 / p)
return n + amount - (k * (amount + y) ** (-p)) ** (1 / (1 - p))
```
Pools après un achat YES : `y' = y + amount - shares`, `n' = n + amount` (symétrique pour NO). Hypothèse documentée (ADR-003) : la simulation ignore les ordres limites du carnet, et le remplissage réel peut donc différer. `amount ≤ 0` → `ValueError`.

### Tâche 6 : Service de synchronisation des marchés

**Files :**
- Create : `src/ambre/data_engine/sync.py`
- Test : `tests/integration/test_sync.py`

**Interfaces :**
- Consumes : `ManifoldClient.list_markets`, `map_market`, les dépôts de la Tâche 5.
- Produces :
  - `@dataclass class SyncReport: pages: int, stored_markets: int, new_snapshots: int, duplicate_snapshots: int, ignored: int, invalid: int, completed: bool, error: str | None`
  - `class MarketSyncService` : `__init__(self, client: ManifoldClient, session_factory: sessionmaker[Session], clock: Callable[[], datetime])` ; `async def sync(self, *, max_pages: int = 5, page_size: int = 1000) -> SyncReport`.

Algorithme :
1. Lire `high_watermark_ms` (clé `"markets"`).
2. Paginer avec `before=<id du dernier marché de la page>`. Chaque page est traitée dans **sa propre transaction** : upsert des marchés, insertion des snapshots, écriture des ignorés.
3. S'arrêter quand une page contient un `lastUpdatedTime` ≤ watermark, quand la page est vide ou plus courte que `page_size`, ou à `max_pages`.
4. Le nouveau watermark est le max de `lastUpdatedTime` vu. Il n'est écrit, avec `last_success_at`, **que si toutes les pages prévues ont réussi**. En cas de `ManifoldUnavailable`, les pages commitées restent, `last_error` est rempli, le watermark ne bouge pas, et le rapport porte `completed=False`.
5. Déduplication sans `event_at` : n'insérer que si probabilité ou pools diffèrent du dernier snapshot de ce marché.
6. `source_id = "manifold:/v0/markets"`. `observed_at` = horloge au moment de la réponse. `ingested_at` = horloge au moment du commit.

Toutes ces fonctions sont pures : elles ne font aucune E/S et reçoivent l'heure `now` en paramètre.

**Interfaces :**
- `features.py` :
  - `@dataclass(frozen=True) class FeatureSpec: name, dtype, definition, source, missing_policy` ; constante `FEATURE_SPECS: tuple[FeatureSpec, ...]`.
  - `@dataclass(frozen=True) class FeatureVector: market_id, available_at: datetime, values: dict[str, float | int | None]`.
  - `extract_features(market: BinaryMarket, snap: MarketSnapshot, now: datetime) -> FeatureVector` avec les clés `market_probability`, `total_liquidity`, `volume_24h`, `unique_bettor_count`, `seconds_to_close` (None si `close_at` None), `seconds_since_creation`. `available_at = snap.observed_at`. Si `snap.observed_at > now`, lever `ValueError` (anti-fuite).
- `baselines.py` :
  - `class ProbabilityModel(Protocol): version: str; def predict(self, f: FeatureVector) -> Estimate`
  - `class MarketPriceBaseline` : `version="market-price-v0.1"`, `p = market_probability`, `uncertainty = uncertainty_floor`.
  - `class BaseRateShrinkage` : `@classmethod fit(cls, outcomes: Sequence[str], cfg: PredictionConfig) -> BaseRateShrinkage`. Taux bêta-binomial `rate = (yes+1)/(n+2)`, `rate_sd = sqrt(rate*(1-rate)/(n+3))`. `predict` : `p = w*q + (1-w)*rate`, `uncertainty = sqrt(((1-w)*rate_sd)**2 + floor**2)`, `version = f"base-rate-shrinkage-v0.1(w={w},n={n})"`. Les `inputs` exposent `rate`, `n` et `w`. Docstring : estimateur non validé, utilisé pour produire des opportunités *théoriques*, sans prétention d'avantage (ADR-004).
- `eligibility.py` : `check_eligibility(market: BinaryMarket, snap: MarketSnapshot, now: datetime, cfg: EligibilityConfig) -> list[str]` (liste vide si éligible). Raisons : résolu ; fermé ou `close_at - now < min_seconds_to_close` ; `close_at` None (horizon inconnu) ; `token == "CASH"` ; liquidité None ou < min ; parieurs None ou < min.
- `strategies.py` :
  - `class Strategy(Protocol): name: StrategyName; def evaluate(self, market, snap, estimate: Estimate, total_value: float, risk: RiskConfig) -> Proposal | None`
  - `ValueHunter.evaluate` : `q = snap.probability`, côté = signe de `p - q`. `p_cons = p - u` (YES) ou `p + u` (NO), borné à `[0.001, 0.999]`. Si `p_cons` ne bat pas `q` du bon côté → `None`. Sinon `stake = risk.kelly_fraction * kelly_side(p_cons, q) * total_value`. `reasons` contient p, q, u et le côté. `invalidation` contient `"market moves past p_cons"` et `"estimate uncertainty exceeds edge"`.
  - `NoTrade` : renvoie toujours `None`. Elle existe comme baseline explicite.
- `risk.py` :
  - `@dataclass(frozen=True) class PortfolioView: cash: float, total_value: float, open_exposure: float, open_market_ids: frozenset[str], exposure_known: bool`
  - `class RiskEngine(cfg: RiskConfig)` : `evaluate(self, proposal: Proposal, snap: MarketSnapshot, portfolio: PortfolioView, survival: SurvivalAssessment) -> tuple[RiskVerdict, FillValue | None]`.
  - Ordre des contrôles, chaque refus ajoutant une raison : `not survival.allow_new_positions` ; `not exposure_known` ; marché déjà en position ; `stake = min(proposal.stake * survival.stake_multiplier, max_position_fraction*total_value, cash, max_total_exposure_fraction*total_value - open_exposure)` ; `stake < min_stake` → refus. Puis `fill = cpmm_fill(...)` et `assess_fill(p_cons_side, fill, fee_rate)`. Si `ev_per_mana < minimum_edge`, refus avec la raison `"edge after impact X < 0.03"`. Approuvé : `RiskVerdict(True, stake, reasons)` et le `FillValue`.
- `survival.py` :
  - `@dataclass(frozen=True) class SurvivalInputs: total_value: float, peak_value: float, initial_capital: float, data_age_seconds: float | None, exposure_known: bool, halted: bool`
  - `assess_survival(inp: SurvivalInputs, cfg: SurvivalConfig, risk: RiskConfig) -> SurvivalAssessment`. Règles dans l'ordre, la première qui s'applique gagne :
    1. `halted` → HALTED.
    2. `total_value ≤ failure_value_fraction * initial_capital` → HALTED, raison `"failure: portfolio value ≤ 50% of initial capital"`.
    3. `not exposure_known` ou `data_age_seconds is None` ou `> max_data_age_seconds` → OBSERVING.
    4. `drawdown ≥ critical_drawdown` → CRITICAL.
    5. `drawdown ≥ defensive_drawdown` → DEFENSIVE (multiplicateur 0.5).
    6. Sinon BALANCED (1.0).
    `drawdown = 1 - total_value/peak_value`. `allow_new_positions` vaut faux pour HALTED, OBSERVING et CRITICAL.
